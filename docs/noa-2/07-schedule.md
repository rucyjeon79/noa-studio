# 7. 확인된 운영 상태와 복구 지점

2026-10-20 새 Work에서 GitHub와 정식 `https://noastudio.ai.kr`을 대조했다.
과거의 이 파일에 적혀 있던 “배포 전·이관 전” 상태는 현재 상태가 아니다.

| 구분 | 확인 결과 | 증거와 검증 한계 |
|---|---|---|
| 복구 기준 | `fee93ad` 이후 이어서 수정 | 기존 저장소 전체 소스 복구. 새 사이트나 프리뷰를 만들지 않음 |
| 정식 배포 | 기존 NOA 파일 61개가 저장소와 일치 | SSH/SFTP SHA-256 대조. 그누보드 핵심 10개 파일 변경 없음 |
| 음악 원본 | 15개 장르, 653개 문서가 저장소에 있음 | 원본 JSON 유지. DB 전체 payload 일치 여부는 이번에 재검증하지 못함 |
| 공개 음악 | 287개 문서 표시 | 정식 음악 화면, 검색·장르 필터, 공개 catalog 확인 |
| 공통 화면 | 홈·설정·그누보드 로그인 연결 확인 | 기존 PC/모바일 디자인 검증 기록도 유지 |
| 재생 수정 | 준비 전에 누른 재생 요청 보존, 초기 볼륨 반영, 지연 안내 | `deploy/noa-music.php`만 서버에 변경. 회귀 테스트 3개와 PHP 문법 검사 통과 |
| 실제 YouTube 재생 | 미검증 | 마지막 기존 진단은 `verified:false`, 봇 확인 메시지. 진단 종료를 재생 성공으로 표시하던 스크립트도 수정 |
| DB 보존 검증 | 이번 작업에서 DB 쓰기 없음 | 호스팅이 PHP CLI와 SSH DB forwarding을 거부. 관리자 세션의 기존 `/noa-bridge/source-audit.php`로만 후속 검증 |
| AI LAB | 운영 완료 아님 | 기존 생성·음량 처리 소스 보존. 기존 생성 코드는 xAI에 연결됨. 새 운영용 Node/AI 연동은 확인되지 않음 |
| NOA GROWTH LAB | 운영 완료 아님 | 하이라이트·1분 이내 16:9 MV/립싱크·YouTube 성장/업로드 요구 유지. 해당 운영 구현과 인증 연결은 확인되지 않음 |
| 최종 지시서 | 회수 한계 있음 | 이전 대화 검색 오류로 최종 지시서 전문을 회수하지 못함. 기존 요구를 임의 삭제하거나 완료로 처리하지 않음 |

복구 검증 워크플로: `.github/workflows/noa-recovery.yml`.
음악 원본, 회원, 환경설정, 그누보드 핵심 파일을 초기화하거나 덮어쓰지 않는다.
정식 적용은 기존 버전의 SHA-256이 확인되는 NOA 파일에 한정한다.
서버 DB 조회 제한을 풀거나 인증을 우회하는 엔드포인트는 만들지 않는다.
