# Grok 뮤비 생성기 — 최고관리자 AI LAB 통합

원본: https://github.com/rucyjeon79/noa-muvy/tree/c4303f80288a7f696eb9164f0900c50b61829554

기존 PHP/GnuBoard AI LAB의 `#lab-muvy` 단계에 원본의 제작 흐름을 이식한다. 별도의 회원 시스템이나 새 홈 화면을 만들지 않는다. 화면, API, 직접 패널 주소 모두 기존 로그인과 `is_admin === 'super'`를 기준으로 접근을 제한한다.

## 제작 흐름

1. EP 번호·제목·가사를 서버에 저장하거나 기존 CinemaPack JSON / Zustand `{state:{pack}}`을 가져온다.
2. Grok으로 30컷 대본과 곡 타입·감정선·챕터 의상을 생성한다.
3. 챕터마다 5컷씩 두 번 요청하여 Gemini 이미지 프롬프트와 Grok 영상 프롬프트를 만든다. 앞 묶음 성공 후 뒷 묶음이 실패하면 완료된 묶음을 다시 호출하지 않고 이어간다.
4. 챕터별 보충컷을 두 개씩 추가한다. 최대 8개이며 원래 30컷은 보존한다.
5. YouTube 제목·설명·커뮤니티 글·썸네일 프롬프트를 만들고 JSON 또는 Markdown 제작 문서를 받는다.

원본 저장소의 생성물은 대본과 프롬프트 패키지다. 이 통합 역시 MP4 렌더링을 완료한 것으로 표시하지 않는다. 이미지·영상은 Gemini/Grok에서 프롬프트로 제작할 수 있고 기존 AI LAB의 음원·영상 영역으로 이동할 수 있다. 자동 YouTube 게시는 실행하지 않는다.

## 저장과 요청 검증

- 서버 웹 루트 밖 기존 비공개 AI LAB 폴더에 별도 `muvy.json`을 원자적으로 저장한다. 기존 작업·회원·음원 SQL과 AI LAB 작업 목록은 수정하지 않는다.
- 생성 요청 전 작업 버전과 단일 실행 상태를 확인한다. 동일 요청 ID는 유료 공급자 재호출과 사용 횟수 중복 차감을 막는다.
- 30컷 전체 순서, 챕터별 5컷 번호, 메타데이터, 의상, 제목의 원제목·EP 포함 여부를 검증한다. 잘못된 출력은 기존 초안을 덮어쓰지 않는다.
- 생성은 관리자 버튼 조작으로만 실행한다. 기본 상태는 비활성이고 키가 없으면 생성할 수 없다. 공급자 오류에 대해 자동 유료 재시도하지 않는다.
- xAI 키는 기존 AES-256-GCM 저장 기능을 사용한다. 브라우저에는 설정 여부만 전달한다. 기본 모델은 원본의 `grok-4.5`, 관리자 변경 가능. 요청당 출력 토큰 상한과 일일 요청 횟수 제한을 적용한다.
- 새 원제목·가사로 작업하면 기존 제작 결과를 보존한 별도 초안으로 저장한다. 내보내기는 브라우저 다운로드로 제공한다.

## 검증 범위

CI는 격리된 PHP 서버와 GnuBoard 로그인 인터페이스, 결정적 공급자 응답을 사용한다. 실제 회원으로 로그인하거나 유료 xAI 생성을 호출하지 않는다. 운영 검증은 소스 SHA 확인, 기존 보호 파일 보존, 실제 비로그인 접근 차단이다. 실제 xAI 키 등록·모델 권한·생성 결과는 관리자가 연결한 계정으로 실행할 때 확인된다.

공급자 공식 문서 확인: https://docs.x.ai/developers/model-capabilities/text/structured-outputs 및 https://docs.x.ai/developers/rest-api-reference/inference/chat-completions (2026-10-26). 원본 Chat Completions JSON 계약을 유지하며 응답 구조를 서버에서 다시 검증한다.
