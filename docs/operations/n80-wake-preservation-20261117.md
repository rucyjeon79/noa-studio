# N80 예약 신호 보존 수정 — 2026-11-17

개선방의 마지막 운영본 2.1.477 이후 작업을 이어받아, 예약 신호가 32건을 넘으면 이전 미처리 기록까지 잘리는 결함을 수정했다. 운영 2.1.478의 최신 원본을 기준으로 3개 파일만 직접 배포했으며, 결과는 **2.1.479**다.

## 변경

- 32건이 저장되면 새 슬롯은 `wake_store_full_review_required`로 거절한다. 기존 기록과 nonce를 수정하거나 미확정 기록을 자동 삭제하지 않는다.
- 같은 슬롯의 중복 신호는 저장 한도에 도달해도 새 작업을 만들지 않는다.
- Hub 잠금 안에서 구형 heartbeat·batch 실행 금지 정책도 다시 확인한다.
- 읽기 전용 감사 결과에 저장 한도, 남은 자리, 신규 접수 차단 여부와 후속 조치를 추가했다. 저장소 이상 시 남은 자리는 미확인으로 보고한다.
- 공개 진입점은 한도 초과를 HTTP 409로 구분한다. 활성화·서명·시간창·호스팅 승인 검사를 우회하지 않는다.

## 검증

- PHP 8.2.35 WebAssembly 런타임에서 수정 파일 문법 검사 및 예약 계약·신호 저장·감사·호스트 카나리 테스트 통과.
- 31/32/33건 경계, 미확정 기록 보존, 한도 도달 후 중복, 과다 저장 기록 보존, 저장 직전 정책 변경을 검증했다. 이 테스트의 승인은 로컬 합성값이며 운영 승인이 아니다.
- 예약 정책 검사 222개: 위반 0개. 구형 실행기 재접속 차단 테스트 통과.
- 배포 ID: `587b86dbae6873b1474ca27d317f1646`. 운영 서버 재조회에서 3개 파일의 SHA-256이 배포값과 일치했다.
- 운영 관리 API 정상, 복구 필요 없음. 새 감사 필드 반환 확인: 신호 0건, 보관 한도 32건, 남은 자리 32건.

## 유지한 상태와 미완료

- 구형 상주 실행기 4개 부재. 프로세스 목록은 직접 관찰하지 않았다.
- `ai.batch` 미확정 영수증 1건 보존. 재실행·정리하지 않았다.
- 예약 신호 자동 실행은 비활성이다. 현재 수신 기록 0건이므로 실제 서명 수신·실제 업무 처리는 미검증이다.
- 닷홈 허용 증거, 전용 서명키 설정, 실제 제한된 단발 업무 실행기와 Gemini·Flow·YouTube 연결 검증이 남아 있다.
- 이번 변경은 신호 유실 방지 수정이다. 무인 제작·YouTube 게시 완료가 아니다.
