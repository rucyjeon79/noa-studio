## 1. 최상위 명령 — 기존 작업 중단 금지

현재 수행 중인 NOA STUDIO 2.0 전체 정상화 작업을 그대로 이어서 진행한다.

오늘 추가된 지시는 기존 지시를 대체하지 않는다.

**기존 미완료 작업에 추가 등록하고, 중복되는 항목은 하나의 작업으로 통합한다.**

다음 사항을 준수한다.

1. 현재 진행 중인 작업과 마지막 성공 단계를 확인한다.
2. 기존 완료 사항은 다시 개발하지 않는다.
3. 오늘 추가된 지시를 기존 작업 목록에 누적한다.
4. 다른 Work의 변경사항을 보호한다.
5. 이미 확정된 디자인과 기능은 재승인받지 않는다.
6. 기존 GitHub Actions 자동배포를 사용한다.
7. 실제 운영 검증까지 완료한다.
8. 완료 증거가 없는 항목은 미완료로 유지한다.

**PR 병합이나 코드 작성만으로 완료 처리하지 않는다.**

## 2. P0-01 — JUKEBOX 업로드 최적화 정체 및 오류

오늘 확인된 업로드 문제:

- 업로드 최적화 단계에서 멈춤
- `network_unavailable`
- `request_timeout`
- 상태 조회 실패
- 업로드 대기열에서 진행되지 않는 곡 발생

오류 기록에서 `stage: status`, `stage: queue`, `http: 0`이 확인됐다.

### 작업 지시

- 업로드 큐 상태 전수조사
- 서버 응답 지연 및 네트워크 오류 원인 추적
- 업로드 ID 생성·저장·복원 과정 확인
- 상태 조회 재시도 및 제한 시간 검토
- FIFO 대기열 복구
- FFmpeg 최적화 작업 상태 확인
- 실패 작업과 진행 중 작업 구분
- 중복 업로드·중복 변환 방지
- 새로고침 후 작업 상태 복원
- 모바일 네트워크 전환 시 안전한 복구

**기존 업로드 원본과 정상 MP3는 절대 삭제하지 않는다.**

## 3. P0-02 — AI 생성 버튼 무반응

오늘 실제 운영 화면에서 확인된 문제:

YouTube 제목, 영상 설명란, 커뮤니티 글 등에 있는 **AI 생성** 버튼을 눌러도 반응이 없다.

### 조사 항목

1. 버튼 이벤트 연결 여부
2. 실제 API 요청 발생 여부
3. 서버 엔드포인트 존재 여부
4. OpenAI API 연결 상태
5. API 인증정보 및 모델 설정
6. 권한·포인트 정책
7. 오류 발생 시 화면 표시
8. 생성 결과 입력칸 반영
9. 생성 결과 저장 과정

### 구현 기준

- API 연결이 없으면 명확한 안내 표시
- 요청 중에는 진행 상태 표시
- 성공하면 생성 결과를 해당 입력칸에 반영
- 실패하면 원인을 사용자에게 표시
- 중복 클릭으로 중복 과금되지 않도록 처리
- 생성 결과는 사용자가 검토한 후 저장
- 기존 내용을 동의 없이 덮어쓰지 않음

**버튼만 만들어 놓고 실제 기능이 없는 상태를 허용하지 않는다.**

- 이미지 프롬프트
- 캐릭터 고정 프롬프트

8. 복원 후 실제 MUSIC·YouTube·관리자 화면 확인

**기존 곡 정보를 손상시키거나 빈 값으로 덮어쓰지 않는다.**

## 5. P0-04 — SQL과 JSON 저장 역할 정리

기존 설계와 현재 구현 사이의 차이를 검수한다.

### 확정 운영 원칙

**MySQL은 운영 데이터의 기준 저장소다.**

JSON은 API 데이터 표현, MySQL JSON 컬럼, 임시 작업 상태, 감사·백업 메타데이터 등 필요한 용도로만 사용한다.

별도 JSON 파일이 곡 정보의 독립 원본으로 사용되고 있다면 조사한다.

동일 곡 정보가 여러 저장소에서 서로 다르게 관리되는 구조를 제거하거나 동기화 규칙을 명확히 한다.

### 검증

- 원본 수정 시 카탈로그 반영
- 카탈로그 수정 시 원본 보존
- 충돌 시 임의 덮어쓰기 방지
- revision 기반 동시 수정 보호
- 누락 필드 자동 검사
- 데이터 복원 가능성 확보

## 6. P0-05 — 디자인 지침 강제 적용

오늘 확인된 문제:

**확정된 디자인 지침이 존재하는데도 실제 화면에서 지켜지지 않는다.**

### 디자인 제0원칙

iOS처럼 깔끔하고 정돈되며 고급스럽고 세련된 디자인.

### 디자인 제1원칙

꾸며진 박스 안에 다시 꾸며진 박스를 사용하지 않는다.

### 컬러 시스템

- White: 기본
- Gold: 포인트·강조
- Green: 활성·성공
- Gray: 비활성
- Red: 오류·위험
- Blue: 정보
- Amber: 주의
- Purple: AI·창작

### 개선 작업

- 공통 디자인 토큰 통합
- 중복 CSS 제거
- 상충하는 선택자 정리
- 불필요한 `!important` 축소
- 페이지별 중복 카드 스타일 제거
- 버튼·아이콘·여백·타이포그래피 통일
- 실제 카드 이미지와 곡 제목 정렬
- 모바일 화면 겹침 제거
- 하단 내비게이션 가림 방지
- JUKEBOX 확정 2줄 구조 유지

### 자동 검증

GitHub Actions에 디자인 검증 단계를 추가한다.

최소 검사:

- 모바일 가로 넘침
- 카드·버튼 겹침
- 이미지 비율
- 터치 영역
- 중첩 카드
- JUKEBOX 2줄 구조
- 주요 화면 스크린샷 비교

**디자인 검증 실패 시 운영 배포를 통과시키지 않는다.**

## 7. P0-06 — AI 서비스 연동 구조 명확화

Grok Build와 달리 NOA STUDIO는 독립 PHP·MySQL 웹사이트다.

실시간 AI 생성 기능에는 외부 모델 API 연동이 필요할 수 있다.

### 기능별 분리

- 음악·가사 검색: 자체 SQL 처리
- 기존 곡 설명 표시: 자체 데이터 사용
- 실시간 AI 대화: API 연동
- AI 제목·설명·커뮤니티 글 생성: API 연동
- 이미지·영상 생성: 해당 생성 서비스 연동
- FFmpeg 음원 최적화: 외부 생성 AI 불필요

### 필수 구현

- AI 서비스 설정 상태 표시
- 관리자 API 연결 상태 확인
- 요청·응답 오류 처리
- 중복 요청 방지
- 사용량·비용 기록
- 회원 권한 확인
- 포인트 정책 연동
- 민감한 API 키 비공개 저장

API 키를 프런트엔드에 노출하지 않는다.

## 8. P0-07 — Work 실행 상태 및 지시 누락 방지

오늘 다시 확인된 불편사항:

- Work가 작업 중인지 대기 중인지 구분하기 어려움
- 입력창이 보인다고 작업 완료 여부를 판단할 수 없음
- 작업 중 추가 지시 시 기존 실행이 끊길 수 있음
- 실행 정체 후 지시사항 일부가 누락될 위험

### N80 작업 관리 요구사항

- 고유 작업 ID
- 기존 지시 원문 보존
- 추가 지시 누적
- 현재 수행 단계
- 마지막 성공 단계
- 마지막 활동 시각
- 진행 중·대기·오류·확인 필요·완료 구분
- 실패 원인 기록
- 재시작 시 미완료 작업 복원
- 실제 완료 증거 연결

**N80이 ChatGPT Work 내부 실행 자체를 제어할 수 있다고 가정하지 않는다.**

N80은 프로젝트 작업 기록과 외부 배포 상태를 보존하고 추적하는 역할을 담당한다.

## 최종 실행 명령

**기존 Work 작업을 중단하거나 초기화하지 말고, 오늘 추가된 모든 지시를 기존 미완료 목록에 누적하라.**

실제 운영 화면과 데이터 검증이 완료될 때까지 미완료 상태를 유지한다.

**대표에게 같은 지시를 반복하게 만들지 말고, 작업을 끝까지 이어서 처리하라.**
