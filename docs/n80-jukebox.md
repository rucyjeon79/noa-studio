# N80 JukeBox

N80 Engine의 `jukebox` 전문 모듈이다. 별도 엔진, 작업 큐 또는 예약 실행자를 만들지 않는다.

- 등록부: `noa-app/engine/jukebox.php` → `registry.php`.
- `player.js`: 기존 인증된 곡 데이터, 단일 audio, 재생 의도, 다음/이전 곡, ACT/개인/추천 대기열, 반복/셔플, 볼륨, 위치 저장과 복원.
- `presentation.js`: 기존 플레이어 UI, 같은 문서를 유지하는 내부 페이지 이동, 영상/미리듣기와의 재생 충돌 조정.
- `system-media.js`: 재생 소유자가 한 번 연결하는 OS 미디어 어댑터. 잠금화면/헤드셋 조작을 공통 API로 보내고, 지원되는 Audio Session의 중단 상태를 복구 실행자와 공유한다.
- `navigation-policy.js`: 페이지 이동과 새로고침 복원에 사용하는 단일 정책. 인증·결제·다운로드·외부 주소는 기존 경로를 사용한다.
- 기존 업로드·음질 최적화·stream/download·재생 집계·개인 목록 저장소는 그대로 연결한다.

`window.N80JukeBox`가 유일한 재생 API다. `NoaMusic`은 같은 객체의 호환 이름이다. 설치된 Android 브리지가 사용하는 전역 접근자는 모듈 내부 상태만 참조하며 별도 상태를 만들지 않는다. Android 브리지가 있으면 브라우저 복구 실행자를 붙이지 않는다.

추천 화면과 내 재생목록은 곡 키로 공통 API를 호출한다. API는 인증된 현재 목록에 없는 키를 재생하지 않는다. 곡 수정·상세 조회·메뉴 이동은 audio를 교체하지 않는다. 재실행 시 기존 모듈을 반환하며 종료·일시정지 이후 자동 복구하지 않는다.

기존 `noa-navigation-player.yml`이 이 모듈의 통합 검증과 배포를 소유한다. `[n80-jukebox]` 변경에서는 겹치는 배포 작업을 실행하지 않는다. 알려진 서버 버전 검사, 후보 커밋 확인, 파일 해시 대조와 실패 시 원복을 유지한다.

검증 범위: 실제 브라우저 음원 재생과 페이지 이동(360/390/768/1280), 중복 초기화·종료·목록·재생 집계 회귀, 기존 Android 브리지와 실제 새 모듈의 결합, 운영 소스 대조. 실제 Android 기기의 화면 잠금/배터리 절약 정책 검증과 APK 재배포는 포함하지 않는다.

## 직접 스트리밍 개선 (후보)

- 유튜브 임베드에 재생을 위임하지 않고 기존 인증된 MP3 URL과 한 개의 audio를 유지한다. 스트림 서버의 인증·접근 권한·Range 응답과 집계 규칙은 바꾸지 않는다.
- 잠깐의 재생 중단은 먼저 기존 버퍼로 재개한다. 실제 네트워크 오류/장시간 정체에서만 스트림을 다시 요청하고 듣던 위치로 이동한다. 오프라인에는 재요청하지 않으며 연결 복귀 시 현재 의도를 확인한다.
- 버퍼링 중에도 일시정지·닫기·OS 정지가 즉시 복구를 취소한다. 과거 재생 요청의 거부가 같은 곡의 새 재생을 취소하지 않는다. 뒤로 탐색하면 진행 기준도 함께 갱신한다.
- 시스템에서 전달한 오디오 중단 상태에서는 복구를 유보한다. 시스템이 active 상태로 돌아온 경우에만 기존 재생 의도를 확인한다. 지원되지 않는 API는 사용하지 않는다.
- 페이지 숨김/복귀는 사용자 정지와 구분한다. 복구 도중의 실제 듣던 위치와 의도를 체크포인트에 남기며 수동 정지 후 자동 재생하지 않는다.
- 최초 선택·제목 수정·닫기에도 잠금화면 메타데이터를 동기화한다. 브라우저가 실제로 종료된 뒤의 재생이나 모든 OS의 절전 예외를 보장하지 않는다.
- Android 브리지가 있으면 브라우저 복구와 OS 어댑터를 연결하지 않는다. 기존 네이티브 서비스가 계속 소유한다.

확인 결과: 2026-11-08 GitHub Actions 42460861327에서 PHP 구문·N80 등록·렌더 검사, JavaScript 회귀 97개, Chromium 360/390/768/1280의 실제 오디오·페이지 이동·단일 audio·MediaSession 명령·버퍼 재개·Android 브리지 호환 및 디자인 검사를 통과했다. 로컬 환경에는 PHP가 없어 해당 실행은 CI에서 수행했다. 별도 구형 검사에는 현재 공개 DOM/인증 정책과 맞지 않는 추출기, 누락된 독립 fixture 의존성·SQL 컬럼, 만료된 과거 artifact 문제가 남아 있으며 이 배포에서 검사를 비활성화하지 않았다. 운영 배포는 승인 후 소스 해시·보호 파일 확인을 거친다. 실제 휴대폰의 화면 잠금·통화·절전 검증은 미완료다.
