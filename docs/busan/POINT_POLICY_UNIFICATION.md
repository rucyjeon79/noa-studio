# 부산지부 ON — 포인트 지급·차감 단일 운영 규칙 (적용 대기)

> 상태: **정책·검증 기준 확립 / 운영 설정 변경 전**. 실제 관리자 DB의 `cf_*_point`와 게시판 `bo_*_point` 값을 확인하지 못한 상태이며, 이 문서만으로 실제 포인트 지급액이 변경되지 않는다. NOA STUDIO 포인트 정책과 분리한다.

## 목적과 단일 기준

1. **단일 회계 원장:** 기존 그누보드의 회원 포인트 합계와 기본 포인트 내역(`insert_point`, `get_point_sum`)을 기준으로 적립·차감·취소를 기록한다. 별도의 '표시 전용 가상 잔액'이나 무기록 가산을 금한다.
2. **단일 사건·단일 영수증:** 활동·회원·원본 글/댓글·KST 일자를 조합한 불변 이벤트 키를 사용한다. 최초 작성·승인 시 한 번만 적립하고, 수정·새로고침·같은 요청 재전송에는 다시 지급하지 않는다.
3. **활동별 동일 금액:** 일반 게시판에서 동일한 활동은 동일한 금액을 적용한다. 민원·비공개·관리자 전용 게시판 등 보상에서 제외할 게시판은 운영 승인 후 명시적인 제외 목록을 만든다. 읽기·다운로드는 차감 여부를 별도 결정하되 특정 게시판만 임의로 음수 설정하지 않는다.
4. **회원 범위:** 승인된 조합원에게만 활동 보상을 부여한다. 승인 전 가입 보상은 적립하지 않으며, 실제 그누보드가 가입 직후 지급하는 구조라면 승인 지연과 중복 지급 문제를 먼저 보완한 뒤 전환한다. 부산지부ON 활동계정·챗지기자·시스템성 글은 자동 보상 제외 대상으로 구분한다.
5. **정정·삭제:** 글/댓글 취소 시 *그 글/댓글의 원 지급 영수증*을 참조해 실제 지급액만 역분개한다. 지급되지 않은 글에 차감하거나 중복으로 회수하지 않는다. 관리자 취소·보상·환수도 사유와 연계 원장 기록을 남긴다.
6. **유료 AI:** `1P=1원`은 AI 서비스 이용료 **내부 정산 기준**이며 현금환급 약속이 아니다. 실제 사용량과 관리자가 설정한 실결제 환산율로 계산한 금액만 원장에 차감한다. 오류·무료 기본 안내·무응답은 0P. 1원 미만 비용은 누적하고 일회 요청 중복 차감을 방지한다. 환산율 미등록·실비 확인 불가일 때 유료 AI를 차단한다.
7. **한도/어뷰징:** 하루 1회 로그인·가입 승인 1회·게시물당 1회·댓글당 1회·추천 중복 금지. 일일 총 적립 상한, 게시물 최소 품질 및 자기추천 지급 여부는 수치 승인 후 적용한다.
8. **전환 안전성:** 기존 회원 `mb_point`, 포인트 원장, 게시물 및 회원등급은 초기화·일괄 재정산하지 않는다. **앞으로 발생하는 활동부터** 규칙 적용. 전환 전/후 잔액 대사와 관리자 승인·복구 영수증을 필수로 한다.

## 운영 항목별 통일표

| 분류 | 트리거 | 기준 금액 | 중복 조건 / 유의사항 |
|---|---|---:|---|
| 가입 | **가입 승인 완료** | 실제 설정값 확인 후 확정 | 회원당 1회, 승인 보류 중 미지급 |
| 로그인 | 한국시간 당일 첫 유효 로그인 | 미확정 | 회원당 KST 하루 1회 |
| 글 작성 | 보상 대상 게시판의 실제 신규 글 | 미확정 | 글 ID당 1회; 수정은 보상 없음 |
| 댓글 | 보상 대상 게시판의 실제 신규 댓글 | 미확정 | 댓글 ID당 1회; 수정은 보상 없음 |
| 추천 | 유효한 추천 수신 | 활성화/지급액 모두 미확정 | 자기추천·중복·취소 대응 선행 |
| 읽기·다운로드 | 승인된 사용 이벤트 | 차감 여부 및 금액 미확정 | 게시판별 임의 설정 금지 |
| 유료 AI 대화 | 완료한 실제 유료 응답 | **실제 사용료에 해당하는 P** | 사용 전 견적 승인, 오류 0P, 중복 차감 금지 |
| 삭제·취소 | 앞선 지급 이벤트의 철회 | **기존 지급액과 정확히 반대 부호** | 같은 지급 이벤트당 1회 |
| 관리자 조정 | 명시적 사유가 있는 승인 | 지정된 ±P | 사유·대상·관리자 영수증 필수 |

**금액을 미확정으로 둔 이유:** 운영 서버 SFTP에서 홈페이지 루트가 보이지 않는 문제가 확인되어, 현재 관리자 DB 값을 검증하지 못했다. NOA STUDIO 포인트 지급표를 부산지부에 가져오지 않는다.

## 이관 전 점검표

- [ ] 운영 관리자 `cf_use_point`, `cf_register_point`, `cf_login_point`, `cf_point_term` 확인
- [ ] 전체 보상 대상 게시판의 `bo_write_point`, `bo_comment_point`, `bo_read_point`, `bo_download_point` 확인
- [ ] 관리자 메뉴·자동화·독자 후크가 동일 사건에 포인트를 이중 지급하지 않는지 확인
- [ ] 개인정보 없는 샘플 원장으로 과거 사건 중복 여부·삭제 환수·기존 잔액 일치 검증
- [ ] 지급액·일일 상한·예외 게시판 최종 승인
- [ ] 소규모 테스트 계정으로 지급·차감·취소·정산 테스트
- [ ] 배포 전 백업·원복 계획·운영 원장 대사 및 실제 포인트 0건 무단 수정 확인

`config/busan-point-policy.json`은 점검 대상과 금액 미확정 상태를 코드로 표현하는 **제안 설정**이다. 원장에 쓰기 권한은 없으며, 운영DB에 배포하거나 자동 적용하지 않는다.
