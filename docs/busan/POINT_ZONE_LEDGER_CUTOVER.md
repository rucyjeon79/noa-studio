# 부산지부 POINT ZONE 운영 원장 전환 체크리스트

상태: 운영 적용 금지 / 개발 후보 검증 단계. 운영 테이블, 회원 잔액, 기존 코어 파일 수정 없음.

## 확정된 근거
- 45527741652: 기존 회원 및 포인트 원장 MyISAM, yc5_ 쇼핑몰 InnoDB.
- 45535376037: SFTP 인증 성공, 90개 파일 중 21개 포인트 처리 후보, 제외 13개, CLI 메타데이터 응답 실패. 전체 쓰기 경로 확인 아님.
- 45535758300: 공식 그누보드 스키마 기반 단일 원장·주문·재고·취소·반환 격리 DB 검증 통과.
- 신규 native-order-port.php: 기존 원장만 사용하는 포트 후보. 별도의 운영 잔액/포인트 원장 없음. 두 후보 테이블은 요청 중복 방지와 원 거래 영수증용이며 운영 생성 전.

## 운영 전환 순서 (승인 및 검증 후에만 실행)
1. 실제 운영 스키마, 회원 승인 기준, 포인트 사용 설정과 유효기간, 기존 포인트 함수 및 확장 파일의 동시성 규약을 확인. 기본 적립/삭제/만료, 관리자 조정, 선물, AI, 예약 작업 및 직접 SQL 처리 경로를 모두 검토한다. 확인된 21개 파일에만 검토 범위를 한정하지 않는다.
2. 운영 회원/포인트 데이터의 기밀 백업을 웹루트 밖에 보관하고 복구 테스트. 백업의 생성 시각·SHA-256·테이블별 행 수 및 스키마를 기록하되 원본 회원 정보 및 자격 증명을 GitHub나 로그에 올리지 않는다.
3. 전체 원장 쓰기 작업을 일시 정지할 유지보수 창을 확보. 웹 요청뿐 아니라 예약 작업도 포함. 읽기 전용 상태에서 회원 잔액과 원장 합계, 고아 원장 행, 포인트 할당 및 만료 불일치, 중복 이벤트 후보를 대사. 불일치가 발견되면 임의로 잔액을 재계산하거나 초기화하지 말고 중단한다.
4. 운영과 동일한 스키마 및 익명화된 샘플의 격리 환경에서 MyISAM→InnoDB 전환을 시험. 엔진별 인덱스·컬럼·기본값·문자셋·전체 행 보존 검증. 운영 DDL은 자동 커밋이므로 일반 트랜잭션 롤백으로 복구할 수 없음을 반영.
5. 기존 포인트 쓰기 경로 전체를 동일한 회원 잠금·원자적 트랜잭션 규약으로 검증. 단순 저장 엔진 변경으로는 안전성을 보장하지 않는다. 기존 코어 수정 금지 원칙상 검증된 확장 훅으로 처리할 수 있는지 확인하며, 불가능하면 변경 범위 승인 전까지 판매 활성화 금지.
6. 유지보수 창에서 백업과 복구 검증, 원장 대사 결과 및 승인 확인 후에만 엔진 전환 및 영수증 테이블 설치. 원장 데이터 행이나 잔액을 의도적으로 수정하지 않는다. 전환 후 행 수/스키마/대사 동일 여부 확인.
7. 격리 또는 승인된 테스트 계정에서 기존 적립·선물·AI와 상점의 동시 실행, 중복 요청, 차감·반환, 장애 복구, 회원 승인 및 권한, 순정 영카트 우회 결제 금지 검증. 이미 만료된 결제 원본 포인트의 반환 정책 미확정이므로 해당 취소 경로 활성화 금지.
8. 모든 게이트 통과 후에만 운영 요청 처리기를 연결하고 실제 구매 잠금 해제 여부 확인. 원복 필요 시 먼저 모든 쓰기 정지. 신규 거래가 발생한 후 과거 스냅샷 덮어쓰기 금지; 전환 이후 거래 보존 및 대사 계획을 먼저 수립한다.

## 현재 차단 조건
- 전체 기존 원장 쓰기 경로 및 공통 잠금 검증 미완료.
- 운영 백업 생성 및 복구 검증 미실행.
- 운영 MyISAM 전환 및 대사 미실행.
- 만료된 원본 포인트 반환 정책 미확정.
- 운영 구매 라우팅 및 결제 잠금 해제 미실행.

운영 원장 통합 완료라는 표현은 위 조건이 실제 검증되고 운영 반영 영수증이 확보된 경우에만 사용한다.
